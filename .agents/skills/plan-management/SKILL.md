# プラン管理ルール

## プラン作成の原則

### 1. プランファイルの配置

すべてのプランファイルは `docs/plans/` ディレクトリに配置する。

### 2. プランの上書き禁止

**重要**: 既存のプランファイルを上書きしてはならない。

- 新しいプランを作成する場合は、必ず新しいファイル名で作成する
- ファイル名には内容を表す説明的な名前を使用する
- または、日付ベースの命名規則を使用する（例: `2026-01-25-feature-name.md`）

### 3. プランファイルの命名規則

```
docs/plans/
├── overall-implementation-plan.md  # 全体計画（プロジェクト全体の大きな方向性）
├── spicy-petting-tower.md          # 個別機能のプラン（例: OAuth2実装）
└── 2026-01-26-location-verification.md  # 日付ベースの新規プラン
```

- **全体計画**: プロジェクト全体の大きな方向性や段階的な実装計画
- **機能別プラン**: 特定の機能や大きな変更に関する詳細な実装プラン
- **日付ベース**: 小規模な機能追加やタスクの場合

### 4. プランの更新

既存プランを更新する場合は、以下のいずれかの方法を使用：

1. **プランファイル内に「進捗セクション」を追加**
   ```markdown
   ## 進捗状況

   ### 2026-01-25
   - Phase 1-7 完了
   - Phase 9 完了
   ```

2. **新しいプランファイルを作成し、前のプランへのリンクを記載**
   ```markdown
   # 位置情報検証実装プラン（v2）

   前回プラン: [spicy-petting-tower.md](./spicy-petting-tower.md)

   ## 変更点
   - ...
   ```

### 5. プラン作成時の確認事項

プランを作成する前に、以下を確認：

1. `docs/plans/` に既存のプランがないか確認（Globで検索）
2. 既存プランがある場合は、上書きせず新規ファイルを作成
3. ファイル名が内容を適切に表しているか確認
4. 全体計画との整合性を確認

## プラン作成のワークフロー

```bash
# 1. 既存プランの確認
glob "docs/plans/*.md"

# 2. 新規プランファイルの作成（上書き禁止）
# ✅ 正しい: 新しいファイル名で作成
write "docs/plans/2026-01-26-new-feature.md"

# ❌ 間違い: 既存ファイルを上書き
write "docs/plans/spicy-petting-tower.md"
```

## プランの種類

### 全体計画（Overall Implementation Plan）
- プロジェクト全体のロードマップ
- MVPの段階的な計画
- 主要なマイルストーン

### 機能別プラン（Feature Plan）
- 特定機能の詳細な実装手順
- TDDサイクルに基づいたフェーズ分割
- 具体的なファイル構成とコード例

### タスクプラン（Task Plan）
- 小規模な機能追加やバグ修正
- 1-2日で完了する作業
- 日付ベースの命名推奨

## まとめ

- **上書き禁止**: 既存プランは絶対に上書きしない
- **新規作成**: 常に新しいファイル名でプランを作成
- **命名規則**: 内容を表す説明的な名前、または日付ベース
- **進捗管理**: プラン内に進捗セクションを追加、またはdevlogで管理
