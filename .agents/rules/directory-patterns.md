## ディレクトリ配置規則

```
.agents/
  rules/          # プロジェクトルール
  skills/         # スキル
docs/
  prd/            # PRD（要件定義）。00 が全体定義、01〜 が領域別
  design/         # UIデザイン（.pen）と設計判断の記録
  tech/           # 技術的制約とサービス選定。00 が制約、01 が選定
  plans/          # 実装プラン（plan-management スキルの規則に従う）
```

### docs/design には ui.pen 以外を置かない

- `ui.pen` … **確定UI。仕様の正。** フレーム名と NOTE が一次情報
- 旧 UI や UI 作成時の指示書・提案・修正記録は置かない。現行 UI と食い違って認識を誤らせるため
- UI から導いた要件と確定した判断は `docs/prd/` に書く

### docs/tech は PRD より下位

- PRD が確定させた要件から**技術的制約**を導き、それに対して**サービスを選定する**
- PRD の記述と矛盾する制約をここで作らない。PRD の前提そのものが技術的に誤っている箇所は「訂正・補足」として分離して記録し、PRD 側の判断に委ねる
- 価格は必ず**公式の料金ページを一次情報とし、取得日を併記する**。記憶や要約記事から書かない

### 実装コード

技術スタック未定のため、配置規則は選定後に定義する。候補と提案は `docs/tech/01-service-selection.md` にある。
