## 1. この領域が担うこと

設定、アカウント管理、退会、そして**サービスがユーザーに対して行っている約束の記載**（29 利用規約・課金ポリシー / 64 返金について）。

**規約に書いてあることは実装しなければならない。** この領域の最重要事項は機能の設計ではなく、**既に UI 上で約束している内容と実装を一致させること**である。

---

## 2. 規約とヘルプが矛盾している（最優先）

### 2.1 矛盾の内容

| 画面 | 記載 |
|---|---|
| **29 利用規約・課金ポリシー** | 「判定に異議がある場合は**7日以内に再審査を申請できます**」<br>「再審査で**誤検知が確認された場合、全額を返金します**」 |
| **64 返金について** | 「確定した課金は**原則として返金できません**」<br>「返金されない場合: **判定に納得できない**、うっかり忘れた、体調が悪かった」 |

29 は再審査の申請権と返金を明示的に認めており、64 は判定への不服を返金対象外としている。**29 は規約であり、法的拘束力の点で 64 より強い。**

### 2.2 解決: 両立する読み方を採り、文言を揃える

2つは対象が違うと読めば両立する。

| 区分 | 内容 | 扱い |
|---|---|---|
| **誤検知** | 実際には達成していたのに、システムが未達成と判定した | 再審査の対象。誤検知が確認されれば**全額返金**（29 の通り） |
| **判定への不服** | 実際に未達成だったが、事情（体調・失念）を汲んでほしい | 返金しない（64 の通り） |

この区別を前提に、**両画面の文言を揃える**（§9 #1）。64 の「判定に納得できない」は誤解を招くため、「未達成だったことは認めるが事情を考慮してほしい場合」と書き換える。

### 2.3 再審査の期限は 7 日（29 に合わせる）

PRD-03 §7.2 で「異議申し立ては課金から30日以内」としていたが、**29 が7日と定めている以上、7日が正**。写真の保持期間は30日なので証跡は十分に残る（PRD-03 §7.1）。

**PRD-03 / PRD-04 を修正する。**

### 2.4 再審査の実体

PRD-04 §6.2 の通り、独立した申請画面は作らない。**65 問い合わせの「種類=課金のこと」が再審査の申請にあたる**。ただし規約が申請権を認めている以上、以下が必要になる。

- 65 から送られた「課金のこと」の問い合わせを、**再審査の申請として識別できる状態で受ける**（課金ID の自動紐づけ）
- 申請から結論までの期限を決める（規約に書くなら守る必要がある。現状 29 には記載がない）
- 誤検知と判断した場合の返金処理（PRD-04 §6.4）
- 7日を過ぎた申請を受け付けない旨の表示（48 課金明細に残り日数を出すのが自然）

## 3. 一日の開始時刻（11）

11 設定に「全般 / **一日の開始時刻 06:00**」がある。これは PRD-02 で扱っていなかった概念で、**日付の境界を決める**。

### 3.1 何に影響するか

| 対象 | 影響 |
|---|---|
| ホーム（01）の「今日のマイルストーン」 | 深夜2時に開いたとき、前日の分を出すか当日の分を出すか |
| 繰り返しのインスタンス生成 | 「毎日」のマイルストーンが何時に切り替わるか |
| 実績の集計単位 | 達成率・ストリークの1日の区切り |
| 締切6時間前の凍結（PRD-02 §7.2） | 23:30 締切のマイルストーンは 17:30 に凍結する。日付境界とは独立に動く |

### 3.2 決定案

**一日の開始時刻を、日付境界の唯一の定義とする。** 既定は 06:00。

- 06:00 より前の時刻は、前日として扱う
- 23:30 締切の「就寝準備」は当日の分。深夜1時に開いても、まだその日のホームが表示される
- 締切時刻に 06:00 より前（例 02:00）を設定した場合、それは**翌日の 02:00** を指す

深夜に活動するユーザーにとって、0:00 で日付が変わると「昨日の分が消える」体験になる。06:00 を既定にしているのはこのためと読める。

**要確認**（§9 #2）: 一日の開始時刻を変更したとき、既存のインスタンスをどう扱うか。変更の反映を翌日からにするのが安全。

## 4. アカウント（26）

### 4.1 X 連携を削除する

26 のログイン方法に「X / 未連携」の行がある。PRD-01 §3.1 で **X 連携は提供しない**と決定したため、この行を削除する（§10 #2）。

### 4.2 「無料」表示の意味が不明

26 のアカウント名の下に「無料」というラベルがある。**有料プランの存在を示唆するが、UI のどこにも課金プランが存在しない**（ペナルティ課金とは別の話）。

| 解釈 | 対応 |
|---|---|
| 将来の有料プランの布石 | v1 では表示しない（存在しないものを示唆しない） |
| 「利用は無料、課金は未達成時のみ」の意味 | 文言を変える。「基本料金なし」など |

**後者に寄せて文言を変えるか、表示を消す**ことを推奨する（§9 #3）。ペナルティを課すサービスで「無料」と表示するのは、誤解の余地が大きい。

### 4.3 パスワード「未設定」

ソーシャルログインのみのアカウントはパスワードを持たない。この状態でソーシャル連携を解除できてしまうと、**アカウントに入れなくなる**。

**最後のログイン手段を解除できないようにする**（§8）。

## 5. 退会（74）

74 は既に必要な内容を持っている。

- 未確定の課金がある場合、**金額を明示して「未確定の課金は請求されます」と警告する**
- マイルストーン件数（12件 すべて削除）
- 検証履歴・連続記録は復元できない
- 「同じメールで作り直しても記録は戻りません」

### 5.1 未確定の課金があるときの退会

74 は「未確定の課金は請求されます」として**退会を許可する**設計になっている。この方針を維持する。退会を人質に支払いを迫る構造にはしない。

ただし実装上、**アカウント削除後も課金を実行できる必要がある**。

- 決済に必要な最小限の情報（Stripe の顧客ID、課金額、対象インスタンスID）を、課金が決着するまで保持する
- 削除したユーザーへの請求が失敗した場合、再試行できる相手がいない。**PRD-04 §3.3（3回失敗したら放棄）と同じ扱いにする**
- 課金の結果をユーザーに通知する手段が失われる。**退会前に「請求の結果はメールで通知します」と明示し、メールアドレスのみ保持する**必要がある（§9 #4）

この保持は、削除請求と衝突する可能性がある。**法務確認の対象**（PRD-03 §10 #5 と同じ論点）。

## 6. 外観（83）

`ui.pen` の NOTE「外観（テーマ）設定」に決定が記録されている。実装はこれに従う。

- 選択肢: システムに合わせる（既定）/ ライト / ダーク
- **端末ごとに保存し、アカウント間で同期しない**
- 「システムに合わせる」は OS の設定変更に即座に追従する
- プレビューを画面内に表示する（83 が既に持っている）

Web では `prefers-color-scheme` と localStorage の組み合わせで実装する。PRD-01 §3.2 の通り ITP で localStorage が破棄されうるが、失われても既定（システムに合わせる）に戻るだけで実害はない。

## 7. ヘルプ（28）と規約（29）

### 7.1 28 の FAQ 項目

「なぜ課金されたのか / 検証がうまくいかない / マイルストーンを休止したい / 返金してほしい / カードを変更したい」の5項目 + 検索 + 「問い合わせる」。

**「なぜ課金されたのか」が最も引かれる項目**になる。この記事から 48 課金明細への導線を用意する。

### 7.2 特定商取引法に基づく表示の置き場所

v1 は Web で直接課金するため必須（PRD-04 §7）。29 はタブが「利用規約 / 課金 / プライバシー」の3つで、特商法表示の置き場所がない。

**29 に4つ目のタブとして追加する**ことを推奨する（§10 #4）。必要な記載は事業者名・所在地・連絡先・支払い時期・支払い方法・返金の条件。

### 7.3 「App Store で評価する」（11）

11 の「アプリについて」に「App Store で評価する」「アプリを共有する」がある。**v1 は Web なので App Store には存在しない。**

- v1 では「App Store で評価する」を出さない
- 「アプリを共有する」は Web Share API で成立するため残す
- ネイティブ版（Phase 2）で復活させる

## 8. 受け入れ基準

- [ ] 29 と 64 の記載が矛盾していない
- [ ] 課金から7日以内であれば、65 から再審査を申請できる
- [ ] 7日を過ぎた課金について、申請できない旨が表示される
- [ ] 再審査の申請に課金 ID が自動で紐づく
- [ ] 一日の開始時刻より前の時刻は前日として集計される
- [ ] ログイン手段が1つしかないとき、それを解除できない
- [ ] ログイン画面・アカウント画面に X が表示されない
- [ ] 未確定の課金がある状態で退会でき、その金額が事前に表示される
- [ ] 退会後も、未確定だった課金の実行と結果通知ができる
- [ ] 外観の設定が端末ごとに保存され、アカウント間で同期しない
- [ ] v1 で「App Store で評価する」が表示されない
- [ ] 特定商取引法に基づく表示に到達できる
