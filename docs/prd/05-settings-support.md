## 1. この領域が担うこと

設定、アカウント管理、退会、そして**サービスがユーザーに対して行っている約束の記載**（29 利用規約・課金ポリシー / 64 返金について）。

**規約に書いてあることは実装しなければならない。** この領域の最重要事項は機能の設計ではなく、**既に UI 上で約束している内容と実装を一致させること**である。

## 2. 規約とヘルプが矛盾している（最優先）

### 2.1 矛盾の内容

| 画面 | 記載 |
|---|---|
| **29 利用規約・課金ポリシー** | 「判定に異議がある場合は**7日以内に再審査を申請できます**」<br>「再審査で**誤検知が確認された場合、全額を返金します**」 |
| **64 返金について** | 「確定した課金は**原則として返金できません**」<br>「返金されない場合: **判定に納得できない**、うっかり忘れた、体調が悪かった」 |

29 は再審査の申請権と返金を明示的に認めており、64 は判定への不服を返金対象外としている。**29 は規約であり、法的拘束力の点で 64 より強い。**

**29 の構造**: 29 は「利用規約 / 課金 / プライバシー」の3タブで、**設計されているのは「課金」タブのみ**である。上記の2文は課金ポリシーの §2「検証の判定」と §3「返金」にあたる。利用規約本文とプライバシーポリシー本文は未設計であり（§10 #4b）、§2.3 の文言修正で手を入れる対象は課金ポリシーのこの2項になる。

### 2.2 現状の義務は 29 が定めるもの

**この2つは解釈で埋まらない。矛盾は実在する。**

29 の「判定に異議がある場合は7日以内に再審査を申請できます」に条件は付いていない。誤検知に限るとは書かれておらず、**判定に対する異議であれば何でも申請できる**と読むのが素直である。64 はその同じ「判定に納得できない」を返金対象外と宣言している。

**規約が支配する。** 文言を変えるまでは、**課金から7日以内に申し立てたユーザー全員に再審査の義務を負う**。

### 2.3 提案する修正（法務確認が必要）

以下は現状の説明ではなく、**両画面の文言をこう変えるという提案**である。実装・公開の前に法務の確認を要する（§9 #1）。

| 区分 | 内容 | 扱い |
|---|---|---|
| **誤検知** | 実際には達成していたのに、システムが未達成と判定した | 再審査の対象。誤検知が確認されれば**全額返金** |
| **判定への不服** | 実際に未達成だったが、事情（体調・失念）を汲んでほしい | 返金しない |

- 29 の「判定に異議がある場合」を「**判定が誤っていると考える場合**」に限定する
- 64 の「判定に納得できない」を「**未達成だったことは認めるが事情を考慮してほしい場合**」に書き換える

**どちらの画面も、変更が確定するまでは現状の記載が有効である。** 先に実装だけを狭めることはできない。

### 2.4 再審査の期限は 7 日（29 に合わせる）

**再審査を受け付ける期間は課金から7日以内とする。** 29 課金ポリシーがそう定めている。写真の保持期間は30日なので、証跡は期間内を通じて残る（PRD-03 §7.1）。

### 2.5 65 は申請フォームとしての要件を満たしていない

PRD-04 §6.2 で「独立した異議申し立て画面は作らない。65 が兼ねる」としたが、**現状の 65 は自由記述の問い合わせフォームであり、申請を受け付ける仕組みを持っていない。**

規約が申請権を認めている以上、以下が必要になる。

| 必要なもの | 現状の 65 |
|---|---|
| 課金から申請を開始する導線 | **無い**（48 に導線が無い。PRD-04 §6.3） |
| 申請が受理されたという記録 | 無い。送信して終わり |
| 課金側の状態「再審査中」 | 無い。PRD-04 §2.1 の状態にも存在しない |
| 結論（誤検知と認めた / 認めなかった）の記録と通知 | 無い |
| 7日の期限管理 | 無い |

**これは「タグ付きメール」では満たせない。** 課金に状態を持たせ、申請と結論を記録する必要がある。

**決定（要判断・§9 #5）**: 次のどちらかを選ぶ。

| 案 | 内容 |
|---|---|
| A | **65 に申請のセマンティクスを持たせる**。種類=課金のこと かつ 課金が紐づいている場合を「再審査の申請」として扱い、課金の状態を「再審査中」に遷移させる。画面は増やさないが、裏側の仕組みは申請フローとして作る |
| B | **専用の申請画面を作る**。48 から遷移し、対象の課金・理由・証跡の確認を1画面にまとめる |

**A を推奨する**。ユーザーから見た入口は 65 のままでよく、必要なのは裏側の状態管理である。ただし「画面を作らない」ことと「仕組みを作らない」ことは別であり、**PRD-04 §2.1 の課金状態に「再審査中」を追加する**必要がある。

加えて以下を決める。

- 申請から結論までの期限（規約に書くなら守る義務が生じる。現状 29 に記載はない。§9 #6）
- 誤検知と判断した場合の返金処理（PRD-04 §6.4）
- 7日を過ぎた課金には申請導線を出さない（48 に残り日数を表示する）

## 3. 一日の開始時刻（11）

11 設定に「全般 / **一日の開始時刻 06:00**」がある。これは PRD-02 で扱っていなかった概念で、**日付の境界を決める**。

### 3.1 何に影響するか

| 対象 | 影響 |
|---|---|
| ホーム（01）の「今日のマイルストーン」 | 深夜2時に開いたとき、前日の分を出すか当日の分を出すか |
| 繰り返しのインスタンス生成 | 「毎日」のマイルストーンが何時に切り替わるか |
| 実績の集計単位 | 達成率・ストリークの1日の区切り |
| 締切6時間前の凍結（PRD-02 §7.2） | 23:30 締切のマイルストーンは 17:30 に凍結する。日付境界とは独立に動く |

### 3.2 決定案

**一日の開始時刻を、日付境界の唯一の定義とする。** 既定は 06:00。

- 06:00 より前の時刻は、前日として扱う
- 23:30 締切の「就寝準備」は当日の分。深夜1時に開いても、まだその日のホームが表示される
- 締切時刻に 06:00 より前（例 02:00）を設定した場合、それは**翌日の 02:00** を指す

深夜に活動するユーザーにとって、0:00 で日付が変わると「昨日の分が消える」体験になる。06:00 を既定にしているのはこのためと読める。

**要確認**（§9 #2）: 一日の開始時刻を変更したとき、既存のインスタンスをどう扱うか。変更の反映を翌日からにするのが安全。

## 4. アカウント（26）

### 4.1 X 連携を削除する

26 のログイン方法に「X / 未連携」の行がある。PRD-01 §3.1 で **X 連携は提供しない**と決定したため、この行を削除する（§10 #2）。

### 4.2 「無料」表示の意味が不明

26 のアカウント名の下に「無料」というラベルがある。**有料プランの存在を示唆するが、UI のどこにも課金プランが存在しない**（ペナルティ課金とは別の話）。

| 解釈 | 対応 |
|---|---|
| 将来の有料プランの布石 | v1 では表示しない（存在しないものを示唆しない） |
| 「利用は無料、課金は未達成時のみ」の意味 | 文言を変える。「基本料金なし」など |

**後者に寄せて文言を変えるか、表示を消す**ことを推奨する（§9 #3）。ペナルティを課すサービスで「無料」と表示するのは、誤解の余地が大きい。

### 4.3 パスワード「未設定」

ソーシャルログインのみのアカウントはパスワードを持たない。この状態でソーシャル連携を解除できてしまうと、**アカウントに入れなくなる**。

**最後のログイン手段を解除できないようにする**（§8）。

## 5. 退会（74）

74 は既に必要な内容を持っている。

- 未確定の課金がある場合、**金額を明示して「未確定の課金は請求されます」と警告する**
- マイルストーン件数（12件 すべて削除）
- 検証履歴・連続記録は復元できない
- 「同じメールで作り直しても記録は戻りません」

### 5.1 未確定の課金があるときの退会

74 は「未確定の課金は請求されます」として**退会を許可する**設計になっている。この方針を維持する。退会を人質に支払いを迫る構造にはしない。

ただし実装上、**アカウント削除後も課金を実行できる必要がある**。

- 決済に必要な最小限の情報（Stripe の顧客ID、課金額、対象インスタンスID）を、課金が決着するまで保持する
- 削除したユーザーへの請求が失敗した場合、再試行できる相手がいない。**PRD-04 §3.3（3回失敗したら放棄）と同じ扱いにする**
- 課金の結果をユーザーに通知する手段が失われる。**退会前に「請求の結果はメールで通知します」と明示し、メールアドレスのみ保持する**必要がある（§9 #4）

この保持は、削除請求と衝突する可能性がある。**法務確認の対象**（PRD-03 §10 #5 と同じ論点）。

## 6. 外観（83）

`ui.pen` の NOTE「外観（テーマ）設定」に決定が記録されている。実装はこれに従う。

- 選択肢: システムに合わせる（既定）/ ライト / ダーク
- **端末ごとに保存し、アカウント間で同期しない**
- 「システムに合わせる」は OS の設定変更に即座に追従する
- プレビューを画面内に表示する（83 が既に持っている）

Web では `prefers-color-scheme` と localStorage の組み合わせで実装する。PRD-01 §3.2 の通り ITP で localStorage が破棄されうるが、失われても既定（システムに合わせる）に戻るだけで実害はない。

## 7. 問い合わせ（65 / 65b）

`ui.pen` の NOTE「問い合わせの返信先メール」に決定が記録されている。実装はこれに従う。

### 7.1 65 と 65b の使い分け

| 画面 | 対象 | 入力欄 |
|---|---|---|
| 65 問い合わせ | アカウントにメールアドレスがある場合 | なし。「登録メールアドレスへ返信します」とだけ表示する |
| 65b 問い合わせ（メール未登録） | 未ログイン（匿名）・X 連携のみなど、返信先メールアドレスを持たない場合 | 「返信先メールアドレス（必須）」欄と、なぜ必要かの説明を表示する |

- 送信ボタンは、65b ではアドレスの形式が正しいときだけ有効にする
- 65b で入力したアドレスをアカウントにも登録するかは要検討（現状はこの問い合わせの返信にのみ使う想定。§10 #7）

### 7.2 v1 で 65b に到達するユーザーがいるか

PRD-01 §3.1 で X 連携を提供しないと決定したため、**v1 のログイン手段（Google / Apple / メール+パスワード）はすべて返信可能なメールアドレスを伴う**。「未ログイン（匿名）」「X 連携のみ」という 65b の想定トリガは、匿名ログインがネイティブ専用（PRD-00 §8）である v1 では原則として発生しない。

唯一残る候補は、Apple の「メールを非公開」機能で発行される `@privaterelay.appleid.com` 宛のメールが不達になるケースである（PRD-01 §3.1）。ただしこれは「メールアドレスが無い」ではなく「登録済みのメールアドレスへの配信が失敗する」状態であり、65b が前提とするトリガ（メール未登録）とは性質が異なる。

**65b を v1 に残すか、どのような条件で表示するかは未決のまま**（§10 #6）。本節は 65 / 65b それぞれの画面が持つべき挙動を UI に合わせて記録するにとどめ、v1 での適用条件は別途判断する。

## 8. ヘルプ（28）と規約（29）

### 8.1 28 の FAQ 項目

「なぜ課金されたのか / 検証がうまくいかない / マイルストーンを休止したい / 返金してほしい / カードを変更したい」の5項目 + 検索 + 「問い合わせる」。

**「なぜ課金されたのか」が最も引かれる項目**になる。この記事から 48 課金明細への導線を用意する。

### 8.2 特定商取引法に基づく表示の置き場所

v1 は Web で直接課金するため必須（PRD-04 §7）。29 はタブが「利用規約 / 課金 / プライバシー」の3つで、特商法表示の置き場所がない。

**29 に4つ目のタブとして追加する**ことを推奨する（§10 #4）。必要な記載は事業者名・所在地・連絡先・支払い時期・支払い方法・返金の条件。

### 8.3 「App Store で評価する」（11）

11 の「アプリについて」に「App Store で評価する」「アプリを共有する」がある。**v1 は Web なので App Store には存在しない。**

- v1 では「App Store で評価する」を出さない
- 「アプリを共有する」は Web Share API で成立するため残す
- ネイティブ版（Phase 2）で復活させる

## 9. 受け入れ基準

- [ ] 29 と 64 の記載が矛盾していない
- [ ] 課金から7日以内であれば、65 から再審査を申請できる
- [ ] 7日を過ぎた課金について、申請できない旨が表示される
- [ ] 再審査の申請に課金 ID が自動で紐づく
- [ ] 65 はメールアドレスがある場合、入力欄を表示しない
- [ ] 65b はメールアドレスが無い場合のみ表示され、必須の返信先入力欄を持つ
- [ ] 一日の開始時刻より前の時刻は前日として集計される
- [ ] ログイン手段が1つしかないとき、それを解除できない
- [ ] ログイン画面・アカウント画面に X が表示されない
- [ ] 未確定の課金がある状態で退会でき、その金額が事前に表示される
- [ ] 退会後も、未確定だった課金の実行と結果通知ができる
- [ ] 外観の設定が端末ごとに保存され、アカウント間で同期しない
- [ ] v1 で「App Store で評価する」が表示されない
- [ ] 特定商取引法に基づく表示に到達できる
