# ui.pen を参照UI（Alarmy/SuperAlarm）に寄せるための変更案

作成日: 2026-08-15
対象ファイル: `docs/design/ui.pen`
参照: Alarmy(SuperAlarm) スクリーンショット4枚（睡眠 / アラーム編集 / アラーム一覧 / 分析）

## レビュー範囲と前提

実際に見た画面は以下の8つ。ファイルには約90のトップレベルフレームがあるが、
同じパターンの繰り返しなので、以下は**画面単位ではなくパターン単位の提案**。
38a〜38f、テンプレ手順1〜4、設定系にも同じ指摘がそのまま当てはまる。

- 01 ホーム / 03 マイルストーン作成 / 21 テンプレート選択
- 55 カスタム罰金（シート） / 59 テンプレ手順4 罰金
- 04 実績 / 10 課金・支払い履歴 / 11 設定

現状の色バインド率（調査結果）:

| 対象 | トークン参照 | ハードコードhex |
|---|---|---|
| ホーム | 100 | 33 |
| 他5画面 | 436 | 92 |

つまり **8割はトークン経由**なので、トークンを変えるだけで全画面に効く変更が
かなりある。残りのハードコードは主に `#FF453A**`（赤の各アルファ）、
`#FF9F0A**`（橙）、`#FFFFFF0A〜1F`（白の薄い重ね）。

## 0. 着手順序に関する前提（これを先にやらないと工数が跳ねる）

このファイルには **reusable component が 0 個**。ボトムナビは45画面、
ステータスバーは82画面に、それぞれ独立したノードツリーとして複製されている。

ただしノード名は一貫している（`Tab Bar` / `Tab 実績` / `Chip Label` /
`Icon Box` / `Preset Label` など）ので、選択肢は2つ。

- **A. コンポーネント化してから直す** — ボトムナビ、マイルストーン行、
  ピル、カードシェル、ステータスバーを `reusable: true` にして、
  各画面を `ref` に差し替える。初期コストは高いが以後の変更が1箇所で済む。
- **B. 名前マッチのスクリプト一括置換** — `Get(visitor)` で名前一致ノードを
  拾って `Update` する。初期コストは低いが、変更のたびに毎回スクリプトを書く。

見た目の探索を何度も回すなら A、今回の寄せ切りで終わりなら B。
どちらにせよ「1画面ずつ手で直す」は避けたほうがいい。

## 1. 罰金まわり（名指しされた箇所・最優先）

Alarmy には罰金という概念がないので、**コピーできる部品が存在しない**。
ここは翻訳ではなく設計判断になる。方針を1つに絞って提案する。

### 方針: 赤を「クローム（枠・チップ・アイコン・バー）」から全部抜き、数字だけに残す

現状は赤が構造そのものに使われている。

- 罰金カードの枠線 `#FF453A**`
- 選択中プリセット `¥1,000` の枠線＋文字
- カスタム罰金シートの入力枠
- ペナルティ履歴のアイコンチップ背景
- 実績の合計ペナルティ、曜日別バーの赤い棒

これを「赤は**金額の数字にだけ**」に統一する。そうすると赤が、
Alarmy における黄色と同じ役割（モノクロの中に稀に置かれる強調）になる。
金額の重さは色ではなく**サイズ**で出す。

### 具体案

**55 カスタム罰金（シート）**
- 赤枠の入力ボックス → 枠なしのグレーカード（`$surface-2`, radius 24）
- `¥1,500` は据え置きで巨大（現状のサイズ感でよい）、色は赤のまま or 白
- テンキーは現状のままでよい（Alarmyのミッションキーパッドと近い）
- 「決定」の黄色フルワイドピルは参照UIの「保存する」と一致。維持

**03 マイルストーン作成 の罰金ブロック / 59 テンプレ手順4**
- 赤枠カード → 枠なしグレーカード
- プリセットチップ `¥100 / ¥500 / ¥1,000 / カスタム`
  → **黄色アウトライン + 黄色文字**（参照画像2の曜日◯と同じ扱い）に変更。
  赤の枠・赤の文字はやめる
- 見出し「未達成時の罰金」は小さいグレー、金額を大きく — 現状維持でよい

**59 テンプレ手順4 の余白**
- 現状は下2/3が空白のまま。参照UIの余白の取り方（画像1のヘッダー下）は
  意図的だが、ここは間延びして見える。金額カードを縦に伸ばすか、
  「この設定だと月あたり最大 ¥X」のような補助情報を1行入れると持つ

## 2. 参照UIに対応部品があるのに、旧形式が残っているところ

### 2-1. 選択状態が「黄色ベタ塗り」になっている

参照UIで黄色ベタ塗りが使われるのは **主CTAボタン1つ / トグルON / FAB** だけ。
選択状態は**黄色のアウトライン + 黄色文字**（曜日◯）か、
**チェック + 黄色文字**（平日/週末）で表現されている。

現状ベタ塗りになっているもの:

- 03作成の曜日 月火水木金（7個中5個が黄色ベタ）
- 03作成の「今日」「平日」
- 21テンプレの「すべて」
- ホームの日付ストリップの「日 9」

→ すべて **背景透明 + 黄色1.5pxアウトライン + 黄色文字** に置換。
曜日は角丸長方形ではなく**正円**にすると参照UIとほぼ同じになる。

これは1画面あたりの見た目のインパクトが一番大きい変更。

### 2-2. ボトムナビのアクティブタブが黄色

参照UIは3画面とも **グレーの角丸チップ + 白のアイコン/ラベル**。
現状は「黄土色チップ + 黄色アイコン + 黄色文字」。

→ チップを `$surface-2`、アイコンとラベルを白に。
これだけでナビの「安っぽさ」がかなり取れる。

### 2-3. FABが2つある（ホーム）

ホームには右下に黄色の `+` FAB と、ナビバー中央にめり込んだ
グロー付き黄色カメラFAB の**2つ**がある。参照UIは右下に1つだけ。

→ カメラは検証の中心機能なので**消さずに移動**する。案は2つ。
- (a) 右下FABをカメラにして、`+` は一覧画面のヘッダーかナビ中央に逃がす
- (b) 右下FABは `+` のまま、カメラ起動は各マイルストーン行の右側ボタン
  （既に存在する）に一本化する

どちらにしてもナビバーは中央の切り欠きをなくして **5タブ均等のピル**に戻す。
FABの形は正円ではなく **squircle（角丸28前後の正方形）**が参照UIに近い。
グロー（外側の黄色シャドウ）は参照UIにないので削除。

### 2-4. カードに黄色い枠線が付いている

ホームの「作業開始確認」「就寝準備をする」行、作成画面のタイトル入力欄などに
`#FFD60A4D` の枠線が付いている。参照UIのカードは**すべて枠線なし・影なし**で、
背景色の差だけで面を分けている。

→ 枠線を全廃し、強調が必要な行は背景を `$surface` から `$surface-2` に
上げるだけにする。

### 2-5. カードの角丸が小さい

現状 `radius-card` = 18（Alarmyテーマ）。参照UIのカードは 24〜28 くらい。

→ トークンを 24 前後に上げる。これは**トークン1つの変更で全画面に効く**。
同様に `r-22`（→28、FAB/ピル用）も見直す。

### 2-6. アイコンチップの形と色

「Alarmyにはチップがない」は誤り。参照画像4の
「オブジェクトスキャンミッションを解除」行には角丸正方形のチップがある。
違うのは**形と色**。

- 参照: **角丸正方形（squircle）** + 彩度のあるニュートラル色（ティール等）、
  もしくは**チップなしの素の線アイコン**（設定・分析の各行）
- 現状: **正円** + 黄土色/オリーブ色のティント

→ 正円 → 角丸正方形（radius 12〜14）に変更。
設定画面のリスト行は**チップを外して線アイコンだけ**にすると参照UIに近い。
黄土色ティントは全体的にくすんで見えるので、`$surface-2` のニュートラルへ。

### 2-7. モーダル/作成画面のヘッダー構成

- 参照: 閉じる×は **右上のグレー正円**。タイトルバーはなく、
  その下に**大きな状態文**（「2日後にアラームが鳴ります」）が来る
- 現状: ×は左上、中央に「新規マイルストーン」というタイトル

→ ×を右上に移し、中央タイトルを削除。代わりに大見出しを1行入れる
（例:「いつまでに、何をする？」「達成できないと ¥1,000」）。

### 2-8. 作成画面のセクションが「黒地にベタ置き」になっている

参照画像2は、設定項目が**1セクション＝1グレーカード**で完全に区切られている
（時刻ピッカー / 繰り返し / 名前 / ミッション / サウンド）。
「繰り返し」のラベルも曜日◯もカードの**中**にある。

現状の03作成画面は、検証方法4ボタン・今日/明日・繰り返しがすべて
黒地に直置きで、締切時刻と罰金だけがカードになっている。

→ 各セクションをグレーカードで包む。ラベルもカードの中に入れる。
これで画面全体のリズムが参照UIに揃う。

### 2-9. 下部ボタンが2つある

参照UIは下部の主ボタンが**常に1つ**（保存する / スリープ）。
現状の03作成は「プレビュー」＋「作成」の2つ。

→ プレビューはヘッダー右のアイコンか、テキストリンクに落として、
下部は黄色フルワイドピル1つにする。

### 2-10. ヘッダーのコピーが「名詞」になっている

参照UIは **小さく太いアプリ名 → 大きな状態文** という組み立て。
「SuperAlarm」→「2日後にアラームが鳴ります」。

現状は「今日」→「マイルストーン」で、大きい行が名詞なので情報量がない。

→ 大きい行を状態文に変える。例:
- 「あと2件・¥1,800がかかっています」
- 「今日はあと2件」

ほぼコストゼロで、参照UIらしさが一番出る変更。

## 3. 参照UIに対応部品がないところ（設計判断が要る）

### 3-1. ホームの4分割カラープログレスバー / 曜日ドット

黄・赤・橙・グレーの4色バーと、日付ストリップ下の色付きドット。
参照UIにこの表現は一切ない（参照UIの色数は実質 黒・白・グレー・黄の4色）。

→ 進捗はすでに右のリング（1/4）で表現できているので、**カラーバーは削除**。
曜日ドットは参照画像4のカルーセルインジケータのように
**モノクロのドット**（達成=白、未達成=`$text-muted`）にする。
どうしても未達成を区別したいなら、赤ではなく**中空のドット**で。

### 3-2. 実績画面（ここが一番の借用チャンス）

参照画像4は、実績画面にほぼそのまま移植できる構成になっている。

| 参照画像4 | 実績への適用 |
|---|---|
| 「起床成功 1回 / 過去12か月」+ GitHub草ヒートマップ | 「達成 N回 / 過去12か月」の草カード |
| 🔥1 連続日数 / 🏅1 最長連続日数 の2枚並び | そのまま流用可能 |
| ロック解除カード + 進捗ドット | 「連続7日で〇〇解除」等に転用可 |

一方、現状の **曜日別バーチャート（黄/赤/オリーブの棒）** と
**検証方法別の色付きプログレスバー** は、ファイル内で最も参照UIから遠い。

→ 曜日別バーは**草ヒートマップに置き換え**を第一案とする。
残すなら棒は全部 `$accent` の単色にして、未達成分は背景グレーの高さで表す
（色分けをやめる）。
検証方法別は色付きバーをやめて、**数値＋モノクロのドット列**にする。

### 3-3. 課金・支払い履歴の月次バー

グレーの棒＋当月だけ黄色、という表現は参照UIになく、値の大小も読めない
（3月の棒と5月の棒の高さ差に意味が見えない）。

→ 草ヒートマップに寄せるか、リストの上に大きな数字だけ置いて
バーは落とす、のどちらか。

## 4. 工数の切り分け

### トークン1つ変えれば全画面に効くもの

- `radius-card` 18 → 24、`r-22` → 28（カードとFABの角丸）
- `surface` / `surface-2` の明度差の調整
- `danger` の使いどころを絞る前提で、値自体は据え置き

### 名前マッチのスクリプト一括で効くもの（ノード名が揃っている）

- `Tab Bar` / `Tab 実績` / `Tab 設定` … アクティブタブの色（45画面）
- `Status Bar` 系（82画面・今回は変更不要）
- `Chip Label` / `Preset Label` / `Day Label` … 選択チップのベタ塗り→アウトライン
- `Icon Box`（134個）… 正円 → 角丸正方形
- FABのグロー削除

### 画面ごとに手作業が要るもの

- 03作成のセクションのカード化（レイアウト構造の変更）
- ヘッダーのコピー書き換え（画面ごとに文言が違う）
- ホームのFAB統合とナビ中央の埋め戻し
- 実績・課金のグラフ差し替え（新規パーツの設計）
- 59テンプレ手順4の余白の埋め方

### ハードコードhexの掃除（トークン化してから一括）

`#FF453A14/1A/26/30/40/73`、`#FF9F0A/1F`、`#9C7400`、`#E5B83C` あたりが
直書きされている。トークンに寄せておくと以降の色調整が1箇所で済む。

## 5. 効果が大きい順の着手候補

1. 選択状態をベタ塗り → 黄色アウトライン（2-1）
2. ボトムナビのアクティブタブを白に、FABを1つに統合（2-2, 2-3）
3. カードの黄色枠線を全廃、角丸を24へ（2-4, 2-5）
4. 罰金まわりの赤をクロームから抜く（1）
5. ヘッダーのコピーを状態文に（2-10）
6. 03作成のセクションをカード化（2-8）
7. 実績を草ヒートマップ構成に置き換え（3-2）
