### 質問への回答

**Col 火 が暗かった理由**
達成率を3段階で色分けする意図があった（`$accent` 高 / `#9C7400` 中 / `$danger` 低）。
ただし `#9C7400` はトークンではないベタ値で、棒の高さが既に同じ情報を表しているため
中間段は冗長だった。火・日を `$accent` に統一。木・土の `$danger` は
「未達成の多い曜日」という実質的な signal であり、週ストリップのドット色とも対応するため維持。

**ジムのアイコンだけ灰色だった理由**
規則性はなかった。同じく未来の予定である「就寝準備をする」が `$accent` だったため、
状態を表す区別ではなく不整合と判断し `$accent` に統一。
なお 52 一覧の `Row Icon` の灰色はトグルOFF行と対応しているため意図的な状態表現とみなし、変更していない。

### AI感の除去（79 ライブアクティビティ）

8状態すべてが「ステータスピル＋タイトル＋大数値＋進捗バー＋全幅ボタン」の
同一テンプレートだった点がテンプレート臭の原因。以下を状態ごとに削除:

- 終了状態（05 達成 / 06 課金確定 / 07 決済失敗）の進捗バー（常に100%で無意味）
- 05 / 06 の全幅ボタン、04 判定中のダミーボタン「判定を待っています」
- 01 の汎用ボタン「マイルストーンを開く」
- タイトルが状態を述べている箇所の重複ピル（07）、タイトル側の重複語（05「起床確認 達成」→「起床確認」）

結果セル高が 135〜198px に分散し、均一グリッド感が解消。
実アクションが残るのは 02 / 03「いま検証する」、07「カードを更新」、08「すべて表示」のみ。

## 3. ライトモードの実装方式

既存の `Skin`（Base / Alarmy）軸に加えて `Mode`（Light / Dark）軸で変数をテーマ化し、
画面フレームの `theme` に `{Skin:"Alarmy", Mode:"Light"}` を指定してコピーする方式。
fill を1つずつ置換していないため、以後の色調整は変数側だけで両モードに反映される。

**手順（この順序が重要）**
1. 既存97 root に `Mode:"Dark"` を明示（既定値解決でダークが反転するのを防ぐ）
2. トークンに Light 値を追加
3. ベタ値のクローム色をトークン化（824ノード）
4. `theme` 指定つきで86画面をコピー

### ライトパレットの方針

比較用の `pal-*`（暖色テラコッタ）パレットには合わせていない。
現行ダークパレット（純黒 + 近黒カード + 彩度の高い黄 `#FFD60A`）の対応物として設計した。

基調はほぼ無彩色のペーパーグレー（`bg` = `#F2F3F0`、`surface` = `#FFFFFF`、
`surface-2` = `#E8E8ED`）。強調パネルの `panel-warm` だけクリーム（`#FDF3DF`）に振っている。

アクセントは役割で2分割した。**面**（ボタン・リング・バー）は `accent` = `#FFD60A` で
ダークと同一。**文字・アイコン**は `accent-fg` = `#9C7400`（深いアンバー）。
黄色文字は白地では読めないが、near-black に落とすとブランド感が消えるため、
黄の色相を保ったまま明度だけ落としている。

## 5. 適用範囲についての判断

- 「同じ要素を含む部分は全て修正」に従い、`【現行】` `【現行整理】` `【Light】` `【Dark】`
  の比較用画面にも 1〜13 の product ルール系修正（トグル化・フィルタ削除・アイコン色・
  Amount Row）を適用した。
- ただし **79 ライブアクティビティのAI感除去だけは `【現行】79` に適用していない**。
  こちらは見た目の質の判断であり、`【現行】` を before スナップショットとして残すため。
  不要であれば `【現行】79` も同じ修正を当てる。
- Progress Panel の件数を `残り2件` → `残り3件`、リングを `1/4` → `2/5`、スロットを4→5に変更した。
  これは指示外の追加修正で、新設した「完了リスト展開」画面が完了2件を明示するため、
  合計5件・完了2件・残り3件と整合させる必要があったことによる。
  リストヘッダの「残り3件」および実際に並ぶ未完了カード3枚とも一致する。

ベース色をダークと同じ `#FFD60A` に揃え、白地でも面が視認できるようアルファを引き上げた。

**変更しなかったもの — `accent-fg`（アイコン・文字）は `#9C7400` のまま**

一度 `accent-icon` トークン（Light も `#FFD60A`）を新設し、
`$accent-fg` を使っていた icon ノード416個を差し替えて検証したが、破棄した。
ライトで `$accent-fg` が乗る背景は `$surface-2`（`#E8E8ED`、135ノード）/
`$surface`（`#FFFFFF`、21）/ `$accent-a12`（淡黄、17）/ `$overlay-chip`（4）で、
すべて明るい面。`#FFD60A` を置くとコントラスト比 1.15〜1.41 になり、
アイコンの線が読み取れなくなる。

`accent-fg` だけの変更ではこの要求は満たせない。ダークと同じ黄をライトで前景に出すには
**下地を暗くする**（`Icon Box` / `Act Icon Box` など94個のタイルを `#2C2C2E` にする）
必要があり、そこまではやらない判断をした。

`accent-icon` トークンは削除済み（参照0件を確認）。

**表からの削除**: `accent-blue` は上の表に記載していたが、
実際にはドキュメントに定義されていない。週末の曜日ラベルはベタ値 `#5B9CFF`（3ノード）。
