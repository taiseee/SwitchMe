## 主要な原則

- 簡潔で技術的な回答を記述し、正確なPythonの例を用いること。
- 関数型・宣言的プログラミングを使用し、可能な限りクラスは避けること。
- コードの重複を避けるため、繰り返し処理やモジュール化を優先すること。
- 補助動詞を使った説明的な変数名を使用する（例：`is_active`, `has_permission`）。
- ディレクトリやファイル名には小文字とアンダースコアを使う（例：`routers/user_routes.py`）。
- ルートやユーティリティ関数には名前付きエクスポートを使用すること。
- 「オブジェクトを受け取り、オブジェクトを返す（RORO: Receive an Object, Return an Object）」パターンを採用すること。

## Python / FastAPI に関するガイドライン

- 純粋関数には `def` を、非同期処理には `async def` を使うこと。
- すべての関数シグネチャに型ヒントを付けること。入力の検証には生の辞書ではなく Pydantic モデルを使用することを推奨。
- ファイル構成：エクスポートされたルーター、サブルート、ユーティリティ、静的コンテンツ、型（モデル、スキーマ）などで整理。
- 条件文において不要な中括弧 `{}` は使用しない。
- 条件が単一行で済む場合、中括弧を省略し、1行で記述する（例：`if condition: do_something()`）。

## エラーハンドリングとバリデーション

- エラー処理とエッジケースへの対応を優先する：
  - 関数の冒頭でエラーやエッジケースを処理すること。
  - ネストの深いif文を避けるため、エラー条件では早期リターンを行う。
  - 正常系（ハッピーパス）は関数の最後に書くことで読みやすくする。
  - 不要な `else` 文は避け、`if-return` パターンを使用する。
  - ガード節（guard clause）を使って、事前条件や無効な状態を早期に処理する。
  - 適切なエラーロギングとユーザーフレンドリーなエラーメッセージを実装する。
  - 一貫性のあるエラー処理のため、カスタムエラー型やエラーファクトリを使用する。

## 依存パッケージ

- FastAPI
- Pydantic

## FastAPI 特有のガイドライン

- 入力検証およびレスポンススキーマには、関数（プレーン関数）とPydanticモデルを使用する。
- 明確な戻り値型アノテーションを伴う宣言的なルート定義を使用する。
- 同期処理には `def` を、非同期処理には `async def` を使用する。
- `@app.on_event("startup")` や `@app.on_event("shutdown")` は最小限に抑え、ライフスパンコンテキストマネージャーの使用を優先する。
- ロギング、エラーモニタリング、パフォーマンス最適化のためにミドルウェアを活用する。
- I/Oバウンドタスクには非同期関数、キャッシング戦略、遅延読み込みを用いてパフォーマンスを最適化する。
- 予期されるエラーには `HTTPException` を使用し、具体的なHTTPレスポンスとしてモデル化する。
- 予期しないエラーの処理、ログ記録、エラーモニタリングはミドルウェアで行う。
- 入出力の検証やレスポンススキーマには Pydantic の `BaseModel` を使用する。

## パフォーマンス最適化

- ブロッキングなI/O操作を最小限にし、すべてのDB呼び出しや外部APIリクエストには非同期操作を使用する。
- Redisやインメモリストアなどを用いて、静的または頻繁にアクセスされるデータのキャッシュを実装する。
- Pydanticを使ってデータのシリアライズ／デシリアライズを最適化する。
- 大規模データセットや大きなAPIレスポンスに対しては遅延読み込み（lazy loading）を用いる。

## 重要な慣習

1. FastAPIの依存性注入システムを利用して、状態や共有リソースを管理する。
2. APIのパフォーマンス指標（レスポンスタイム、レイテンシ、スループット）を優先する。
3. ルートでのブロッキング処理を制限する：
   - 非同期かつノンブロッキングなフローを優先する。
   - DBや外部APIの操作には専用の非同期関数を使用する。
   - ルートと依存関係の構成を明確にして、可読性と保守性を最適化する。
